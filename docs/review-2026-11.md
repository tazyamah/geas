# 改善点のレビュー（2026-11-10）

geas 全体（検査器・生成器・CLI、生成される Rust アプリ、サーバーの実行部、窓つき exe、常駐、外部通信、ブラウザ拡張、MCP の橋渡し）を読んで、脆弱性と足りない機能を挙げた記録。人が読むメモで、強制力は無い。着手したら [roadmap.md](roadmap.md) へ移すか、ここから消す。

- 軽いレビューで、**ほとんどはコードを読んだだけ**。動かして確かめたものは、項目に「動かして確認」と書いた。それ以外は、直す前に再現から始めること。
- 2026-11-08 の脆弱性レビューで直したもの（テスト用の口を `--test` の後ろへ、流れの途中の処理を外に出さない、CSRF・DNS rebinding の対策、生成コードへの文字列の差し込み）は、ここに載せない。
- すでに [roadmap.md](roadmap.md) にある未着手は、重ねて書かずに参照だけ置く。

## 先にやるとよい順

| 順 | 項目 | 理由 |
|---|---|---|
| 1 | 保存の形の移行（B-1） | `.geas` の項目を変えると、動いているアプリの DB が読めなくなる。直す手段が言語にも実行部にも無い |
| 2 | 窓の移動先の検査（A-1） | 数行で直る。いまは保険が効いていない |
| 3 | 外へ出る通信を失わない（A-2） | 落ちた瞬間の 1 件が、記録にあるのに送られないまま消える |
| 4 | CI（B-5） | テストが 18 ファイルあるが、PR で自動には走らない |
| 5 | 呼べる人の区別（B-2） | 「人は仕様書だけを読む」のに、誰が呼べるかは仕様書の外（プロキシ）にある |

## A. 脆弱性・安全

### A-1（中）窓つき exe：窓の移動先の検査が前方一致

`geas/window/src/main.rs` の `with_navigation_handler` は、URL が `geas://` か `http://geas.localhost` で**始まる**かだけを見る。`http://geas.localhost.evil.example/` も通る。`geas://` もホストを見ない。

外のページが窓に載ると、そのページから WebView の IPC が呼べ、仕様書の URL の表にある処理をすべて実行できる（窓版は Host の検査も省いている）。

いまは、画面に外へのリンクを出す書き方が無く、値はエスケープしているので、すぐ踏める道は見つけていない。エスケープの漏れが 1 つ出たときの保険のはずの検査が、効いていない状態。

直し方：URL を解析して、スキームとホストを完全一致で比べる。IPC の受け口でも、呼び出したページの URL を同じ関数で確かめる。

### A-2（中）外へ出る通信（`over http`）：高々 1 回で、失われても分からない

- 送る待ち行列（`Engine.outbox`）はメモリにある。処理がコミットされてから ticker が送るまで（最大 0.3 秒＋通信の時間）にプロセスが落ちると、外部作用の記録（`geas_effects`）には残るのに、送られないまま消える。
- 送信の失敗（接続できない・時間切れ・シークレットが無い）は標準エラーに 1 行出るだけで、待ちは期限まで残る。再送しない。
- 届いた返事（`mock.jobs`）もメモリで、処理へ届ける前に落ちると消える。
- 冪等キーは記録するが、相手には送らない。

再送の方針と冪等キーのヘッダは [roadmap.md](roadmap.md) の「窓つき exe」に未着手としてある。ここで足すのは「落ちたときに失う」点。

直し方の案：待ち行列を DB の表にして、処理と同じトランザクションで入れる。起動のときに、送っていない分を送る（相手が冪等キーを受けることが前提になるので、ヘッダと一緒に決める）。

### A-3（中）`/api/defs` が、定義を丸ごと誰にでも返す

`--test` を付けなくても開いている。返すのは生成物の定義の全部で、流れの途中の処理（外に出さないと決めたもの）の名前と入力、外部作用の通信先の URL、シークレットの名前（値は入っていない）、模擬の設定を含む。

直し方：画面が使う分（画面・問い合わせの列・呼べるルート）だけを切り出して返す。残りは `--test` のときだけ。

### A-4（低〜中）外部作用の記録が増え続け、引数を平文で持つ

`geas_effects` の表は、外部作用を出すたびに 1 行増え、消す処理が無い。引数（投稿の本文、宛先など）をそのまま保存する。読む口は `--test` の `/api/test/state` だけなので、本番では書くだけの表になっている。

直し方の案：保持する件数か日数の上限を置く。個人の情報を含む型に印を付けられるようにして、記録では伏せる（B-9 と一緒に考える）。

### A-5（低）失敗がすべて 400 で、内部の文言をそのまま返す

`http.rs` は、処理・問い合わせの `Err` をどれも 400 にして、メッセージを本文に入れる。入力の誤りと、サーバー側の失敗（DB に書けない、保存の行が読めない、host の応答が読めない）の区別が付かない。実体の名前やキーが外に出る。

直し方：入力の誤りは 400、内部の失敗は 500 にして、500 の詳細はログだけに出す。

### A-6（低）シークレットのファイルの権限を確かめない

`--secrets` のファイルと、窓版のデータ用フォルダの `secrets.json` は、ほかの利用者が読める権限でも、そのまま読む。警告も出さない。OS の鍵置き場は [roadmap.md](roadmap.md) に未着手としてある。それまでの間は、起動のときに権限を見て注意を出すだけでも効く。

### A-7（低）MCP の橋渡し（`mcp_bridge.py`）が 1 行で落ちる

標準入力の 1 行が JSON でないと、`json.loads` の例外でプロセスが終わる。JSON でもオブジェクトでなければ（配列・数）同じ。サーバーの返事の大きさに上限が無い。サーバーの URL は引数をそのまま使う。

直し方：行ごとに例外を受けて JSON-RPC のエラー（-32700）を返す。返事は上限まで読む。

### A-8（低）依存の点検の手順が無い

サーバーと窓の `Cargo.lock` は固定してあるが、既知の脆弱性を調べる手順（`cargo audit` など）と、上げる時期の決まりが無い。部品は `tiny_http` 0.12、`ureq` 2、`rusqlite` 0.37（bundled）、`tao`・`wry`・`tray-icon`。CI（B-5）に入れるのが早い。

## B. 足りない機能

### B-1（高）保存の形の移行

`.geas` で実体の項目を足す・消す・型を変えると、前の版で作った DB の行が読めなくなる。生成した `*_from_json` は項目が無いと失敗し、`Engine.reload_if_stale` は 1 行の失敗で全体を失敗にするので、**どのリクエストも失敗する**はず（コードを読んだだけで、動かしては確かめていない）。DB に定義の版の記録も無いので、起動のときには気づけない。

人がコードを読まない前提では、「項目を 1 つ足した」という仕様書の差分が、動いているアプリを止めることに、誰も気づけない。

案：
- DB に定義の指紋（実体と項目の形）を持ち、起動のときに照合して、合わなければ理由を言って止まる。
- 検査器が、前の版との差（`receipt` が既に読んでいる）から「保存の形が変わった」を出す。項目の追加は、既定値を書かせる。
- 移行の書き方（言語の機能）は、その後で決める。

### B-2（高）呼べる人の区別（認証・役割）

言語に「誰が」が無い。客の操作も、お店の側の操作（入荷・取り下げ）も、届く人なら誰でも呼べる。[server.md](server.md) には「プロキシで絞る」と書いてあるが、どの URL を誰に開けるかが仕様書に出ないので、レビューできない。「自分の注文だけ見られる」も書けない。

案：役割（actor）を宣言し、`resource` の行に呼べる役割を書く。仕様書の URL の表に列を足す。本人の確かめ方（プロキシが付けるヘッダを信じる、など）は環境の要求（`needs`）に出す。

### B-3（中）一覧のページ送りと検索

問い合わせは、当てはまる行を全部返す。件数の上限は [roadmap.md](roadmap.md) の表の 7 で「需要が出てから」。ページ送りと、文字列での検索（部分一致）の書き方は、どこにも挙がっていない。

### B-4（中）バックアップ・書き出し・復元

保存は SQLite のファイル 1 つで、取り方の説明も口も無い。窓版は利用者のデータ用フォルダに置くので、利用者が自分で写すしかない。サーバーは WAL なので、ファイルを写すだけだと壊れた写しになることがある。

案：`geas_server --backup 出力先`（SQLite のバックアップの仕組みを使う）と、[server.md](server.md) への手順。

### B-5（中）CI が無い

`.github/workflows` が無い。`pytest`、生成物の `cargo test`、`clippy`（生成物が panic の書き方を持たないことの強制）、Kani の証明は、手で走らせたときだけ確かめられる。[roadmap.md](roadmap.md) には Windows のビルドだけが案としてある。

### B-6（低）配り方

`pyproject.toml` が無く、`pip` で入れられない。リポジトリを写して `python -m geas` で使う形だけ。版の番号も、生成物の `0.1.0` の固定だけ。

### B-7（低）サーバーの運用

- 終了の合図（SIGTERM）を受けない。処理の途中はトランザクションで巻き戻るが、送る途中の通信（A-2）は失う。
- `/api/health` は、DB を見ずに常に `ok` を返す。
- 数の口（リクエストの数・時間・待ちの件数）が無い。ログ（`geas.route`）から数える形だけ。
- `HEAD` と `OPTIONS` に答えない（どちらも 404）。

### B-8（低）画面の言葉とアクセシビリティ

画面の決まった文言と、エラーの文言は日本語だけ（manifest の `lang` も `ja` の固定）。読み上げ・キーボードだけの操作は、確かめた記録が無い。

### B-9（低）操作の履歴

誰が・いつ・何を呼んだかは、標準エラーのログだけ。B-2 が入ると「誰が」を残せるようになるので、一緒に決める。

## C. 確かめて、問題が見つからなかったこと

- **検査器の落ちにくさ（動かして確認）**：見本の `.geas` 5 つを崩したもの（行を消す・重ねる、記号を差し込む、文字を削る、語を入れ替える）600 件を `geas check` に通して、Python の例外で落ちたものは 0 件。
- 外への通信先は、検査器が `https://ホスト名/パス` の形だけを通す（http・IP の直書き・ユーザー名・`?`・`#` は誤り）。実行部はリダイレクトに従わない。
- 静的なファイルの配信は、`..`・`\`・空の区間を断る。
- SQL は、表の名前が生成物の実体の名前（半角英数）で、値はすべて引数で渡している。
- ブラウザ拡張は、ページから読んだ値とサーバーの答えを、エスケープしてから表示する。権限は `storage` と、サーバーのオリジンだけ。
- 画面（`ui.js`）は、CSP でインラインのスクリプトを止めている。
- 待ちは、検査器が期限を必ず書かせる（待ち続ける待ちは作れない）。
