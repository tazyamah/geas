# モジュールの配り方の経緯

[modules.md](../modules.md) の本文から移した、決めるまでの経緯。現在の仕様ではない。

## 配り方の考え方（2026-10-27 の議論の経緯）

**結論：配る専用の形式（パッケージ）も、署名も、配布の場の仕組みも作らない。配るのはソースそのもの。** 必要なのは、依存と version の明示と、ソースの差し替えに気づける手段だけ。

### 考えの流れ

1. 最初は、公開して他の人が使うことを考えて、検査結果（インターフェース）だけで使えるパッケージを作った。ソースなしでも配れる形にして、型・結果の形・変換まで実装した。
2. しかし、使う側は、どこかの層で裸のソース（Geas か生成した Rust）が付いていないとモジュールを受け入れられない。ソースを隠したい配り手の要求は、ソースなしを許しても満たせない。そこで「ソースを公開しないモジュールは使えない」と決めた。
3. ソースが必須になると、インターフェース（.geasi）が担うのは、ソースが書き換わっていないかの照合だけになった。元の動機だった「ソースを読まずに軽く検査する」は消えた。照合は、ソースへのハッシュの固定で足りる。
4. 署名が守る「誰が出したか」は、配布の場ができて初めて意味が出る。その場はまだ無い。
5. 決め手になった見方：これからのAIによるコーディングは、FSF が描いた「ソースが共有され、誰でも読んで直せる」世界に向かう。AI がソースを読んで取り込み、必要なら直せるなら、箱に入れて渡す価値は小さい。配る物はソースで足りる。配布の場も、ソースを探して取ってくるだけなら git のリポジトリで足りる。専用の形式は、必要が出てから作れば間に合う。

### 残したもの

- **version の明示**：ソースの先頭に `module Geo version "1.2.0"`。使う側は `use "geo.geas" version "1.2.0"` と書いて、依存する版を明示する。違えばエラー。依存のあるモジュールも、同じく `use` に版を書く。
- **ソースのハッシュの固定（任意）**：`use "geo.geas" sha256 "…"`。取り込むソースが差し替わったときに気づける。ハッシュは `sha256sum geo.geas` で取れる。

### 外したもの（作ったが取り消した。PR #39〜#42）

- `geas package`、インターフェース（.geasi）、`dependencies` の記録、ソースなしの取り込み（`sourceless`）、署名。
- 将来、配布の場ができて必要になったら、「版が上がったときに互換が壊れたかの判定（新旧のソースから公開物を取り出して比べる）」と、署名を、あらためて設計する。

## 未決（実装しながら決める）

- 標準のモジュール（仮想日時から実在日時への変換など）の置き場所。
- 同じモジュールを2か所から取り込んだときの扱い（同じ実体にする）。
- 表示名（`///`）の衝突は、モジュールごとに見る。
