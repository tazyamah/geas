# 日時の考え方

geas の基本の立場は、**実在する日時と仮想日時を分けて考える**こと。それ以上は決めない。

- **実在する日時**は、物理型にとても近い。特に指定がなければ、変換先の言語の都合に従う（Rust なら、いまは秒の整数。表示や読み取りでタイムゾーンや暦が要るなら chrono などの標準的なクレート）。言語が決めるのは、時刻と期間（`sec min hour`）の足し引きと比較ができることまで。
- **仮想日時**は、geas を使う人とアプリケーションによって意味が違うので、言語では決めない。分けて考える、という立場だけを決めておく。

実装は、実在する日時の足し引きまで。

## 2つに分ける

| 種類 | 意味 | 持ち方 | geas での今 |
|---|---|---|---|
| 実在する日時 | 時間軸上の一点 | 物理型に近く、変換先の都合に従う（Rust はいま秒の整数）。論理層はほぼ無い | `time`。期間 `sec min hour` を足し引きでき、時刻の差は秒数 |
| 仮想日時 | 「今年の誕生日」のように、時分秒などが未指定で、そのままでは一点にならないもの | 暦の成分（年・月・日など）の組 | 未実装 |

仮想日時は、必要になったときだけ、足りない部分（時分秒・暦・タイムゾーン）を補って、実在する日時に変換される。変換しなければ、実在しない。

## 「1日後」の意味

人が言う「この日から1日後」は仮想日時（日付）の計算で、「86400秒後」は実在日時の計算で、別の物を指す。夏時間などで暦の1日は86400秒と限らない。

- 実在日時の期間に `day`・`week`・`month`・`year` は書けない（書くとエラー）。ちょうどの時間は `24 hour` と書く。
- 暦の単位は、仮想日時の側に付ける。
- タイムゾーンが要るのは、仮想日時と実在日時の変換（どちら向きも）だけで、暦の計算そのものには要らない。

## 未決（必要になったときに決める）

- 仮想日時の種類（日付だけか、月日・年月など成分の組を一般化するか）
- 月末の扱い（1月31日の1か月後）
- 暦とタイムゾーンの与え方（slot で外から与える案がある）
- 夏時間の存在しない時刻・2回ある時刻の解き方

## 組み込みの仮想日時（2026-10-26）

仮想日時は、年・月・日・時・分・秒の成分を持つ合成型で、すべての成分を未指定にできる（`仮想日時 { 月: 10, 日: 26 }` は、年と時分秒が未指定の日時）。
成分の範囲は構造の上限だけ（月 1..12、日 1..31、時 0..23、分・秒 0..59、年 1..9999）で、暦として正しいか（2月30日など）や意味は、アプリの規則で決める。

- 未指定の成分は、確かめずに読めない。未指定にアクセスしうる道があると、検査器がエラーにする（`if 日時.月 is null { return … }` で確かめたあとは読める）。
- 実在する日時（`time`）への変換は、まだ書けない。変換は一方通行の変換の宣言で書く方針で、これから設計する。

## 外から受け取る値と変換（2026-10-26）

外から受け取る値は、境界で内部の論理型へ変換して検証する（読む側の変換で、実行は定義の数まで）。
この変換は生成器が持つので、`raw` のようなキーワードは書かない（書いても検査にも生成コードにも効かないため）。
論理型どうしの変換は `convert 名前(引数: 型) -> 型 = 式` と書く。結果の範囲は、検査器が引数の範囲から静的に示す。

## 仮想日時から実在日時への変換（2026-10-26）

変換は geas の式で書く（暦の計算は整数の足し引き・掛け算・`/`・`%` だけで書ける）。
未指定の成分を補うルールは、変換の引数に `fill { 時: 0, 分: 0 }` と書く。補うルールがある成分は「指定されている」扱いで、読む前の確かめが要らない。ルールがない成分を読む道があれば違反（検査器が止める）。
標準のタイムゾーンは UTC（アプリで別に決めるまで）。ほかのタイムゾーンへの変換は、タイムゾーンの宣言を足すときに設計する。
`time(整数)` は、1970-01-01 UTC からの秒数を実在日時にする。
