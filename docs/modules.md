# モジュール（ファイルの分割と再利用）の設計（2026-10-27）

状態: 段階1（ソースのまま取り込む）を実装済み。tazyamah との議論で決まった方針をまとめる。

## 結論

**モジュールは「状態を持たない」ものに限る。** 型と式の部品の集まりで、entity は持たない。処理（deed）は、状態に触れないもの（入力から結果を返すだけ）なら持てる。状態を持つモジュールは、必要が出るまで入れない。

これで、次の面倒がなくなる。

- 「entity を書けるのは持ち主のモジュールだけ」という検査が要らない（モジュールに entity が無い）。
- モジュールをまたぐ不変条件が起きない（不変条件は、アプリの entity について、アプリの中で書く）。
- 別々に検査した結果を取り込むときに、証明の前提が崩れない。

## 目的と単位

- よく使う定義を、再利用できる単位にする。単位は**業務に特化しない共通概念**（論理日付、標準の論理型・変換・部品、など）。
- 業務の単位（注文など）はモジュールにしない。注文の取り消しには、決済のように作者が知りえない要件が入る。
- 読みやすさのための分割は要らない（Geas のコードは人が読まない）。ファイルが巨大になって悪影響が出るなら、そのとき別に考える。
- 将来、モジュールを先に検査・コンパイルしておき、その結果だけを取り込めるようにする（検査を軽くする）。

## モジュールに書けるもの

- 論理型（`ltype`、合成型を含む）、変換（`convert`）、外から足す部品（`part`）。
- 状態に触れない処理（`deed`）。データの読み書き・状態の遷移・採番・外部作用ができない（検査器が止める）。アプリのフローには `Mod.grade: Pass → reply` の形でつなぐ（式の中から deed を呼ぶ道は、言語にまだ無い）。
- 結果の形（`result`）と、外部作用の宣言（`effect`）。どちらも状態を持たない型・宣言なので共有できる。
- 書けないもの: `entity`、`state`、`query`、`nexus`、`trigger`、`event`、`invariant`、`store`。

## 値の入れ物

- 保存しない・キーで引ける・読み取り専用の入れ物は、`ltype Table = id → Pos` のように、キーが `id` の写像で書く（値は合成型でもよい）。entity を一時的な入れ物に使うと、書込みの命令と状態の入れ物（`保存`）が付いて回るので使わない。Rust では `BTreeMap<String, Pos>` を参照渡しするだけ。

## 型の規則（モジュールの境界でも守る）

- 比較・四則・代入ができるのは組み込み型だけ。論理型は「組み込み型 + 制約」で、演算は元の組み込み型で行う（暗黙の変換。物理は同じで、制約は検査器が見るだけなので、実行時の費用はない）。合成型は成分に分けて組み込み型として読む。
- したがって、モジュールの境界を越えるのは「元の組み込み型 + 制約（範囲など）」だけ。物理型は越えない。
- 不変条件は、アプリの entity について、組み込み型として値を比べる形で書く。

## 約束（言語が守らせること）

1. モジュールは状態を持たない（上の「書けるもの」だけを書ける）。
2. モジュールは循環して取り込めない。
3. 名前は、モジュールごとの名前空間に置く。他のモジュールの名前は `Module.Name` で指す。

## 公開するもの（ヘッダーに当たる部分）

- 型の元の組み込み型と制約、変換と部品の入力・戻り値の型と範囲、結果の形、外部作用の宣言。
- 隠すもの: 物理型、変換や部品の中身。物理型はモジュールが責任を持って決め、外は口を出さない。外が知るのは「元の組み込み型は何か、何に変換できるか」だけ。
- 公開は、既定は非公開で、書いたものだけを公開する。

## 書き方（段階1で決定）

- モジュールのファイルは、最初の文を `module Name` にする。ほかの文は上の「書けるもの」だけ。
- 取り込む側は、ファイルの先頭に `use "geo.geas"`（取り込むファイルからの相対パス）を書き、`Geo.Pos` `Geo.same(x)` の形で指す。
- 実装はトークン列の展開。モジュールの名前を `Geo_Pos` のように改名して取り込み、`Geo . Pos` を改名後の名前に置き換える。同じファイルは1度だけ読む。循環・モジュール名の重なり・書けない宣言・存在しない名前は ModuleError で止まる。
- 名前の書式の検査は元の名前（`Pos`）に対して行う。表示名はモジュール側の `///` を使い、無ければ `Geo.Pos` と出す。
- 変換・部品は、値を返す関数なので lower_snake（`Geo.same`）。

## 段階

1. **ソースのまま取り込む。** ファイルを取り込んで全体を1つのプログラムにして検査・生成する。名前空間を入れる。仕様書に定義したモジュールの欄を足す。
2. インターフェースの出力と取り込み（設計は下の「段階2の設計」）。検査器がモジュールの検査結果から、公開するものと、結果の範囲を出す。使う側は、ソースの代わりにこれを取り込み、自分のコードだけを検査する。生成する Rust は、モジュールごとの crate にできる。モジュールをまたぐ最適化はしない。呼び出しの費用は、小さい関数に `#[inline]` を付けて Rust に任せる。
3. （必要が出たら）状態を持つモジュール、パラメータつきのモジュール。そのときは、「entity を書けるのは持ち主だけ」の検査と、モジュールをまたぐ不変条件の扱いを、あらためて決める。

## 段階2の設計（2026-10-27）

公開して他の人が使うことを考えると、検査結果（インターフェース）だけで使えることは、速度のための最適化ではなく公開の前提になる。

### 配り方（決定：ソースなしでも配れる。2026-10-27 tazyamah）

配るもの（パッケージ）は、インターフェース（`geo.geasi`）と、モジュールから生成した Rust の crate（`geas_mod_geo`）。Geas のソースは入れても入れなくてもよい。

ソースが無いと、使う側は「インターフェースの宣言どおりに crate が動く」ことを検査し直せない。だから信用は、次のように別の手で作る。

- **ハッシュの固定（必須）。** 使う側は、取り込むパッケージの SHA-256（インターフェースと crate の中身）をアプリ側に記録する（`use "geo" sha256 "…"` の形）。違えばエラー。配った後の差し替えと、使っているうちの書き換わりを防ぐ。
- **配る側の署名（任意、あとで）。** 配る人がパッケージに署名し、使う側は公開鍵を信用する。ハッシュ固定が「同じものか」を守り、署名が「誰が出したか」を守る。
- ソースがパッケージに入っているときは、インターフェースの中のソースのハッシュと照合でき、誰でも作り直して確かめられる（信用の度合いが上がる）。入っていなくてもパッケージは使える。
- 検査器は、インターフェースの宣言（範囲・保証）を「配る側の約束」として使う。範囲の宣言に反する値は、モジュールの生成コードが実行時に確かめる（部品の保証と同じ考え方）。

### インターフェースに入れるもの

`geas package geo.geas -o geo/`（`geo.geasi` と crate を出す）で作る。検査器が出すもので、人は手で書かない。

- モジュール名、モジュールの version、検査器の version、ソースの SHA-256。
- 論理型：元の組み込み型と制約（範囲・長さ・文字種）。合成型は成分の名前と型。
- 変換・部品：入力の型、戻り値の型と範囲、部品の保証（式）。中身は入れない。
- 結果の形：種類と中身の型。
- 処理（deed）：入力の型、結果の形。触れるデータは無い（状態を持たないので）。
- 表示名（`///`）。仕様書にモジュールの名前を出すため。

隠すもの：物理型、変換・処理の中身。

### 取り込み

- ソースを使うときは今のまま（`use "geo.geas"`）。パッケージを使うときは `use "geo" sha256 "…"`（パッケージの場所は、アプリ側の設定で決める）。
- 使う側の検査は、インターフェースの型と範囲だけを信じて進める。モジュールの中は検査し直さない。
- 照合する項目：パッケージのハッシュ、モジュールの version、検査器の version（インターフェースを出した検査器と、使う側の検査器が違うとき。互換の範囲は version の付け方で決める）。どれかが違えばエラー。

### 生成する Rust

- モジュールごとに crate（`geas_mod_geo`）を作り、アプリの crate が依存する。モジュールをまたぐ最適化はしない。小さい関数に `#[inline]` を付け、Rust に任せる。
- 物理型の選び方はモジュールの責任。外に出るのは、インターフェースに書いた元の組み込み型だけ。

### 実装の分け方（小さい PR）

1. パッケージの出力（`geas package`：インターフェースと、モジュールの crate）。
2. `use "geo" sha256 "…"` での取り込み（ハッシュの照合、インターフェースだけで検査、crate への依存）。署名は、そのあとで足す。

## 信頼（検査した結果を使うとき）

- インターフェースには、ソースの内容のハッシュ（SHA-256）、モジュールの version、検査器の version を持たせる。取り込むときに照合し、合わなければエラー。
- インターフェースは、人が手で書く宣言ではなく、検査器が出す（宣言は本物の約束、の原則）。
