# 未着手・保留の一覧

人が読む一覧で、強制力は検査器にない。決まったこと（決定）は各 docs に書き、ここは「まだやっていないこと」だけを置く。着手したら消すか、済みに移す。最終更新：2026-11-08。

2026-11-10 の全体のレビューで挙げた改善点（脆弱性と足りない機能）は [review-2026-11.md](review-2026-11.md) にある。ここには重ねて書いていない。制約と部品のレビュー（検査の穴、部品の境界値の検査、足りない言語機能の残り）は [review-2026-11-constraints.md](review-2026-11-constraints.md)。

## 本体の実装

- **geas 本体の Rust 化**（検査器・生成器・CLI。いまは Python で約 9,300 行）。「ちゃんと動くのが先」で、いまは Python のまま進める。生成アプリとサーバー実行部は既に Rust。README の Rust 化予告は残す。
- **raw から convert で境界の値を変換する書き方**。第 1 段（`raw` 型、`require` つきの `convert`、型の `read`、文字位置の `sum`、式の `if`）は実装済み。`check gtin` は、`convert` で同じ判定が書けると確かめたが、組み込みはまだ残している。消すには、画面の固定値の静的確認とブラウザ拡張の事前検査を `read` の変換で動かす必要がある。`trust dangerous`（未検査の `raw` を受けて外へ中継）は実装済み。残り：入れ子の形、`dangerous` の画面でのエスケープ省略（画面に `raw` を出す書き方が決まってから）、`unsafe` を使う場面（いまの生成物には無い）。
- **言語側の標準部品**（ハッシュなど、geas の式で書けない純粋な計算）。`library` の上に、Rust の公開 API から機械で作って載せる（`geas/stdgen.py`）。整数型は済み（`geas/std/num.geas`。生成のときに、安定版の toolchain で組んで端の値で呼び、手本 `geas/stdref.py` と比べる。nightly だけにある関数は外す）。標準部品の Kani の証明は済み（`proofs/std_proofs.py`。248 個のうち 234 個で panic しないこと、うち 125 個で式どおりであることを、全部の入力で示した。結果は同梱の台帳 `geas/std/num.parts.json` から仕様書の「人の保証」に出る）。未着手：`pow` の証明（繰り返しの上限を付ける）、ビット演算の式、時間切れと式の食い違いの区別。bool を返す関数は済み（`bool` 型）。未着手：文字列（str・String）、char、他のクレート、Option を返す関数の扱い。`part` の外部実装は廃止し、`library`（根の言語のライブラリ呼び出し）に置き換えた。

## 窓つき exe（スタンドアロンアプリ）

済み：`--standalone` で窓つき exe の crate を出す（[standalone.md](standalone.md)。画面から処理への呼び出しは IPC、Linux で窓が開くことと IP のソケットを持たないことは試験済み）。外部作用の実通信（`over http`。宣言した先だけ、リダイレクトに従わない、シークレットは環境変数かファイル、仕様書に「外へ出る通信」の表）。ファイル操作（`over file`：write・overwrite・read・delete。触れるのは path 型の引数の下の宣言した相対パス 1 つ。見本 `tests/fixtures/file_demo`）。見本はつぶやき＋X への投稿（`tests/fixtures/solo_tweet`、試験は模擬の X）。データ用フォルダの宣言（`path 名前 = absolute { OS ごとの書き方 }`／`relative`、`data_folder 名前`。相対パスは exe が起点、環境変数は必ずある名前か `needs env`、組む OS の行を `--target` で確かめる）。常駐（`resident`：トレイのアイコン、窓を閉じたら隠す、右クリックのメニューは画面を開く・出来事を起こす・区切り線、左クリックは開閉かメニュー（click）、起動は 1 つ。Linux で作成と重複起動の断りまで試験済み）。未着手：実トレイでのクリック・メニュー・隠れる動きの確認（Windows・macOS）、macOS の Dock を隠す設定、ログイン時の自動起動、OS の通知（外部作用の一種）、アイコンの表示（件数など）を問い合わせから取る宣言、2 つ目の起動で既存の窓を出す。未着手：Windows の exe の実機確認（GitHub Actions の windows-latest でのビルドと selftest が案）。X の本物の API（OAuth の更新、レート制限）での確認。`over http` の拡張（GET、本文以外の入力、再送の方針、冪等キーのヘッダ、シークレットの OS の鍵置き場）。ファイル操作の拡張（フォルダの一覧、追記、移動、宣言した絶対パス（path の値）の下への操作、ファイルの中身の JSON などの解釈）。起動時に保存先を選ぶ入口は、geas の外（アプリの設計）で決める方針（exe の隣に記録するなど。書けない場所は、エラーにする）。

## 「生成時の書き方で保証し、実行時の損失をゼロにする」の議論

方針と決定の記録は [why-spec-and-code-dont-drift.md](why-spec-and-code-dont-drift.md)。1 件ずつ具体例で議論している。

| # | 論点 | 状態 |
|---|---|---|
| 1 | 外の部品・境界確認 | `trust verify／assume` は実装済み（入力の型のみ）。raw から convert の第 1 段は実装済み。`part` の外部実装は廃止し、根の言語のライブラリを呼ぶ `library`（trust 必須、人の保証に出る）に置き換え済み。標準部品は未着手 |
| 2 | 割合の掛け算の桁 | 済み（#78：分母の物理上限と、途中の桁の検査） |
| 3 | 変数で割る割り算 | 済み：割る数が 1 以上と示せるか、`x / d or 0` で 0 のときの値を書く（範囲の宣言と、`if` で止めた先の範囲を使う） |
| 4 | 増え続ける累計（`saturating +=`） | 済み：`+= 式 saturating "理由"`（端で止める）と `+= 式 trust assume "理由"`（届かないと承知）。`update { … += … }` の形には未対応 |
| 5 | 書込適用と同時リクエスト | 直列化は済み（1 リクエスト 1 トランザクションで、直列の保証は DB の書き込みロックが担う。同じ DB ファイルの複数サーバーでも試験あり、panic でも続行）。`storage 保存先 isolation process|store(種類) ["理由"]` で保存先を定義し、保証の範囲を持たせられる。未着手：保存層を契約（trait）として切り出し、別の保存先を足せるようにする。未決：画面の古い値での上書き（版の確認）。期限の発火は、同じ DB を共有する複数サーバーでも待ち 1 件につき 1 回（待ちを消せた 1 つだけが進む、試験あり） |
| 6 | 外から入る値の境界確認 | 1 に含めて対応（`trust` で緩められる） |
| 7 | 資源枯渇 | 一部済み：長さを書かない文字列の既定の上限（1,048,576 文字）、本文 16 MiB の上限（413）、JSON の入れ子 64 段。保存はサーバーがメモリに持ち、DB へは処理が変えた行だけを書く（1 リクエストごとの全件の読み込みと JSON の往復はなくした。別の接続の書き込みは SQLite の `data_version` で見つけて読み直す）も済み。worker の本数（`--workers`）と待ち受けアドレス（`--host`）も済み。読み込みの時間切れは部品（tiny_http）に口がないため、nginx などを前に置く前提で docs/server.md に書いた。未着手：同じ DB を複数台で書き合うときの読み直しを、変わった行だけにする（いまは別の台が書くたびに全部を読み直す）。件数の上限は需要が出てから |

提案済みで未着手：途中の算術すべてを区間で示す、`Unproven` を証拠の再利用でなくす、書込の版の確認（画面の古い値での上書きを止める）。任意で、固定容量の生成による Kani の検証（標準の BTreeMap と String では遅すぎた）。

## 検証・生成：PDD Kit（GitHub Next）から取り込む案

PDD Kit は「AI が書いたコードを、一行ずつ読まずに信頼する」ために Verus の証明を使う研究プロトタイプ。geas に取り込めるものとして挙げた案のうち、済みと未着手は次のとおり。

- 済み：保証の強さを仕様書に出す（「保証の強さ」の表。強い順）。
- 済み：変異検査の `--run --plan`（生き残りを計画書の具体例でも確かめる。お店アプリの計画書は処理の具体例を持たないので、見本は shop）。
- 済み：`geas mutate`（確認を消す、上限の確認を緩める、遷移の宣言を消す、`required` を外す、型の範囲の上限を狭める、要素数の上限を広げる、の 6 種。検査器の反応だけ。`--base`／`--base-git` で変わった行だけ）。結果はお店アプリで見本に固定し、変わったらテストが落ちる（検査は 0.5 秒ほどなので、結果の保存と使い回しは要らない）。未着手：崩し方の追加（`trust` の段階、丸めの指定など）、仕様書の「保証の強さ」への反映。
- 済み：レビュアー目線の質問は、開発用の skill `skills/geas-develop` に入れた（計画書づくりの `plan-interview` には足していない）。未着手：飛ばされる問題が実際に出たら、台帳（`geas/interview.py`）で「未回答なら先へ進まない」を強制する。
- 済み：変更ごとのレシート（`geas receipt`。保証が弱くなったもの・増えた人の保証、保証の強さの件数の変化、変異検査の生き残り、検査の結果。差分 HTML にも同じ節）。未着手：PR の本文への自動の貼り付け（CI）、具体例テストの結果のレシートへの反映。
- 済み（前置きの範囲）：生成物の前置きの Kani の証明（`proofs/`。割合の計算、範囲・割合・文字・GTIN の判定、幅とかなのそろえ）。未着手：`floor` の商と余りの検算（128 ビットで重い）、`fold_text` の大小そろえ（標準ライブラリの `to_lowercase` の表が重く、170 秒で終わらず、メモリ不足も出た。標準ライブラリ任せ）、前置きに入らない処理側の生成コード、Verus のような別の道具の検討。

## 実行環境（動かす前提）

方針の記録は、project のメモリ（geas-environment-direction）。geas は Terraform や Ansible を置き換えず、アプリが環境に要求することだけを宣言し、環境の実際は plan と実環境から読んで照合する。**済み**：`needs`（secret・exposure・instances）、導出する項目、`geas env-checks [--json]`、仕様書とレビュー画面の「動かす前提」の節、中立な事実のスキーマと照合器（`geas env-verify`、判定は合格・不合格・確かめられなかった・人の保証）、aws-ecs のアダプタ（`geas env-facts`。見本の plan は手書きで、**実物の `terraform show -json` とは未照合**）。**未着手**：実物の plan での確かめ、ほかのプラットフォームのアダプタ（k8s、Cloud Run など）、子モジュールの中のリソースの読み取り、シークレットの名前を環境の変数名に結ぶ取り決め（いまの secret は常に「確かめられなかった」）、実環境の検査項目への変換器（goss を第一候補、「条件」つきの一覧から作る）、サーバー起動時の自己点検（シークレットが無ければ起動を拒否）、「保証の強さ」への「環境が担う」の行、レシートへの環境の要求の増減、sqlite を共有ファイルシステムに置く構成の検出。

## AIネイティブ開発ガイド（OpenAI）との比較から取り込んだもの

済み：`check --json`（hint つき）、`mutate --run`、`geas bench`（AI が書く力の採点。PR の直前・ビルドの直前に 1 回）、レシートの影響範囲（`receipt --plan` でユースケースも）、生成サーバーの構造化ログと `geas trace`。未着手：`bench` のケース集（お店アプリなど複数）を置いて前回と比べる運用、`hints.py` の直し方を種類単位から指摘単位に細かくする、ログに時刻の窓や状態の分布を足す、`trace` の画面側（画面の操作ログ）。
