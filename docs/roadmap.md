## 本体の実装

- 生成したアプリの通しテスト（`test_url_examples.py` など）、MCP の橋渡し（`mcp_bridge.py`）、Kani の証明の道具（`proofs/std_proofs.py`）、文書サイトの生成（`tools/build_site.py`）は Python のまま。Rust に移す。
- **raw から convert で境界の値を変換する書き方**の残り：入れ子の形、`dangerous` の画面でのエスケープ省略（画面に `raw` を出す書き方が決まってから）、`unsafe` を使う場面（いまの生成物には無い）。
- **言語側の標準部品**（ハッシュなど、geas の式で書けない純粋な計算）の残り：`pow` の証明（繰り返しの上限を付ける）、ビット演算の式、時間切れと式の食い違いの区別、文字列（str・String）・char・他のクレート・Option を返す関数の扱い。

## 窓つき exe（スタンドアロンアプリ）

- 実トレイでのクリック・メニュー・隠れる動きの確認（Windows・macOS）、macOS の Dock を隠す設定、ログイン時の自動起動、OS の通知（外部作用の一種）、アイコンの表示（件数など）を問い合わせから取る宣言、2 つ目の起動で既存の窓を出す。
- Windows の exe の実機確認（GitHub Actions の windows-latest でのビルドと selftest）。X の本物の API（OAuth の更新、レート制限）での確認。
- `over http` の拡張（GET、本文以外の入力、再送の方針、冪等キーのヘッダ、シークレットの OS の鍵置き場）。
- ファイル操作の拡張（フォルダの一覧、追記、移動、宣言した絶対パス（path の値）の下への操作、ファイルの中身の JSON などの解釈）。
- 起動時に保存先を選ぶ入口は、geas の外（アプリの設計）で決める（exe の隣に記録するなど。書けない場所は、エラーにする）。
- 役割（actor）のあるアプリの窓つき exe 化、移行（migration）の窓つき exe での試験。

## 実行時の保証

- 保存層を契約（trait）として切り出し、別の保存先を足せるようにする。
- 同じ DB を複数台で書き合うとき、別の台が書くたびに全部を読み直している。変わった行だけにする。
- 件数の上限（需要が出てから）。
- `update { … += … }` の形での `saturating +=`。
- `Unproven` を証拠の再利用でなくす。固定容量の生成による Kani の検証（標準の BTreeMap と String では遅すぎる）。

## 検証・生成

- 変異検査：崩し方の追加（`trust` の段階、丸めの指定など）、仕様書の「保証の強さ」への反映。
- 台帳（`interview`）で、レビュアー目線の質問が飛ばされたら先へ進めない強制（飛ばされる問題が実際に出たら）。
- 変更ごとのレシートの PR 本文への自動の貼り付け（CI）、具体例テストの結果のレシートへの反映。
- 前置きの Kani の証明の残り：`floor` の商と余りの検算（128 ビットで重い）、`fold_text` の大小そろえ、前置きに入らない処理側の生成コード、Verus のような別の道具。
- `bench` のケース集（お店アプリなど複数）を置いて前回と比べる運用、`hints` の直し方を種類単位から指摘単位に細かくする、ログに時刻の窓や状態の分布を足す、`trace` の画面側（画面の操作ログ）。
- ユースケースの手順に URL の列を足す。`update`／`destroy` の HTTP 通し試験。手書きの残り（Chrome 拡張、dev の模擬）をなくす。
- 具体例が当たっていない内部 URL と結果の組を、仕様書の「内部 URL ごとの確認の網羅」の「未」からなくす。
- ①（会話で作る仕様書）を別に作る意味の検証。

## 実行環境（動かす前提）

- ほかの基盤（ECS・k8s・Cloud Run など）、クラウドの読み取り系 CLI の出力（`aws ecs describe-services` など）を事実に変えるアダプタ、子モジュールの中のリソースの読み取り。
- 実環境の宛先ごとの到達とシークレットの実在（環境の内側から確かめる口が要る）、シークレットの名前を環境の変数名に結ぶ取り決め（いまの secret は常に「確かめられなかった」）、役割つきのアプリで役割ヘッダを付けた確かめ。
- 仕様書の「人の保証」の横に実環境の結果を並べる、「保証の強さ」への「環境が担う」の行、レシートへの環境の要求の増減。
- 実環境の検査項目への変換器（goss を第一候補、「条件」つきの一覧から作る）、サーバー起動時の自己点検（シークレットが無ければ起動を拒否）、sqlite を共有ファイルシステムに置く構成の検出。

### 実機で確かめる残件（まとめて行う）

実機・実環境が要る。確かめたら、結果をここに書いて消す。

- 生成した Dockerfile を実際に組んで動かす（`geas rust --host --runtime` の出力フォルダで `geas container` → `docker compose up -d --build`）。非 root・読み取り専用のルート・ボリュームの権限（番号 10001）・ヘルスチェック・`--allow-host` が実際に通るか
- VM＋Docker の通し：前段のプロキシ越しに HTTPS で届くか、入れ替え（`docker compose up -d --build`）で新旧が重ならないか、ボリュームのデータが残るか
- `geas doctor` を、コンテナの中とホストの上で実際に走らせる：口・領域の種類（overlay とボリュームの見分け）・時刻同期（timedatectl）・同じ DB を開いているプロセスの数・環境ファイルの権限
- `geas env-live` を、HTTPS の実サーバーに向けて走らせる（https は curl で送る）。役割（actor）つきのアプリの 401・403
- `geas env-probe` の宛先到達（`--egress`）を、実際にファイアウォールで絞った環境で
- aws-ecs のアダプタを、実物の `terraform show -json` で（見本の plan は手書きのまま）
- 仕様書（.md）の構成図（mermaid）が、GitHub や仕様書のビューアで実際に描画されるか

## 呼べる人の区別

- 処理（deed）での範囲の引き方の拡張：`let … else` 以外の形（`データ.範囲[ID].項目`、for で回した中の引き直し）。
- 範囲を役割ごとに分ける。画面ごとに、使える役割を出す（今は、呼べない操作を押すと 403）。
- MCP のツール（ブリッジはヘッダを付けないので、役割のある口は 401 になる）。手元で画面を試すときの役割の付け方（今はプロキシか、ヘッダを付けた呼び出し）。
- 誰が呼んだかをログに残す（[履歴のレビュー](history/reviews/review-2026-11.md)の監査の項）。窓つき exe での役割。
