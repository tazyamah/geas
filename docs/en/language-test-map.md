# Language features and their behavior tests

> This page is a translation of the Japanese original (the Japanese text is the source of truth). Test names in quotes are English glosses of the Japanese test names of the Python version (kept at the git tag `python-final`); search the tag for the Japanese originals.

> **The "behavior test" column gives the names of the Python version's tests, and the "Rust version (now)" column gives where the same check is made in the current repository.** The Python version was deleted at the time of the Rust port and is kept at the git tag `python-final`. The Rust behavior tests are, in `crates/geas-cli/tests/`: `behavior.rs` (deeds, queries, deletion, money), `host.rs` (host boundaries, types, parts, modules), `numbers.rs`, `reliability.rs`, `delete.rs`, `rest.rs`, `actors.rs`, `parts.rs`, `security.rs`, `screens.rs`, `effects_check.rs`, `effects_run.rs`, `env.rs`, `messages.rs`, `spec_steps.rs`, `user_path.rs`, `window.rs`, `runtime.rs` (end to end with the server built), `migration.rs`, `mcp_bridge.rs` `e2e.rs`, and `shop_checks.rs`, `shop_flow.rs`, `shop_effects.rs`, `shop_types.rs`, `shop_lang.rs`, `shop_modules.rs`, `shop_gen.rs`, `shop_tools.rs` and `shop_app.rs`, which hold the individual cases moved from the Python `test_geas.py`; the end-to-end tests on the generated side come out in the output's `server/tests/`. In addition `golden.rs` (the outputs for the 3,894-item corpus match the Python version), `spec_coverage.rs`, `lang.rs` and `container.rs` watch. All Python tests have been moved to Rust except two for the std-bundle generator (stdgen), which existed only in Python (the committed `num.geas` ledger is watched by `parts.rs`).

The guarantee of geas is placed on "if the generator is correct, every app works as its `.geas` says". For that purpose, this table manages, for each item of [language-reference.md](language-reference.md), whether there is a **test that actually runs the generated Rust and confirms it**. When you add a new feature, add a row to this table and write a behavior test.

The meaning of the "run" column is as follows.

- **◎**: Rust generated from a small `.geas` is run, and results, writes and external effects are confirmed.
- **○**: There are only tests in which the checker (static) stops mistakes. The run-time behavior is passed through indirectly by the tests of other items.
- **✕**: There is not yet a behavior check.

The tests that write and run small `.geas` files (the Python version) are in the following places at the tag `python-final`. They confirm feature by feature, without using the shop app.

- `tests/test_behavior.py`: directly runs generated Rust (deeds, queries, deletion, money).
- `tests/test_runtime.py`: builds up to the server runtime and runs parallelism, joins, deadlines, events, rules, idempotency keys, REST statuses, restarts, screens and the extension (the subject is `tests/fixtures/runtime_demo`).
- `tests/test_geas.py`, `tests/test_delete.py`: host boundaries, types, parts, modules, etc.

The shop app's (`tests/fixtures/overseas_shop`) `tests/test_shop_app.py` (below "the shop's end to end") is not a per-feature check but an end-to-end check (E2E) of a real app.
