# `.geas` を書いて、人に仕様書を見せるまで

出典：レビュアー目線の質問と変異検査は、GitHub Next の PDD Kit（Proof-Driven Development）の考え方に倣う。AI が書いたコードを人が一行ずつ読まずに信頼できるようにする、という狙いは geas と同じ。

計画書（`skills/plan-interview` で作ったもの）から `.geas` を書き、検査し、人がレビューする仕様書を作る。**人は `.geas` を読まない**。人が読むのは生成した仕様書だけなので、仕様書を見せる前に、人が引っかかりそうな所を AI が先に潰す。

## 約束

- **1回に聞くのは1問**。短く。長い一覧を見せて全部答えさせない。選択肢（番号）と自由な答えのどちらでもよい形にして、おすすめと理由を1つ付ける（`plan-interview` と同じ）。
- **勝手に決めない**。決まっていないことは、人に聞くか、「未規定」（意図的に決めない）として計画書に書く。
- **人に見せる言葉は平素に**。構文の話をしない。聞くのは約束（定義・保証・意味）が変わることだけ。
- 質問は、仕様書（コードから生成したもの）を読んでも**答えが読み取れないこと**だけ。読み取れることは聞かない。
- 会話に出ていない関係者を掘り起こさない。聞くのは、いま作っているものの**振る舞い**の穴。

## 進め方

1. **`.geas` を書く**。[docs/language-reference.md](../../docs/language-reference.md) と近い例（`tests/fixtures/overseas_shop/`）を見ながら。名前は半角英数、日本語の表示名は直前の `///`。
2. **検査する**（`python -m geas check アプリ.geas`）。エラーは直す。**問い（QUESTION）は、検査器が「決めていない」と見つけたことなので、1問ずつ人に聞く**。答えをもらったらコードに反映して、もう一度検査する。次の問いは、そのあとに聞く。
3. **仕様書を作り、AI が先にレビューする**（`geas spec`／`geas review`）。仕様書をレビュアーとして頭から読み、下の観点で「この仕様書から答えが読み取れるか」を確かめる。読み取れない観点だけを、**1問ずつ**人に聞く。答えは、計画書（具体例の表）とコードの両方に反映する。意図的に決めないなら、計画書の「未規定」に書く。
4. **変異検査を回す**（`python -m geas mutate アプリ.geas`。更新のときは `--base-git HEAD~1` で変わった行だけ）。**生き残り**（崩しても検査器が何も言わなかった約束）は、人に見せて1件ずつ確かめる。守るべき約束なら、不変条件・遷移・具体例に足す。元から冗長な確認なら、そのままにする。
5. **更新のときは、レシートを付ける**（`python -m geas receipt アプリ.geas --base-git HEAD~1`）。保証が弱くなったもの・増えた人の保証を、PR の本文の先頭に貼る。差分 HTML（`review --diff-o`）にも同じ内容が出る。
6. **仕様書を人に渡す**。人が全体を読んで「これで合っている」と言えるかを確かめてもらう。ここで出た指摘は、4 までに潰せなかったものとして、観点を見直す材料にする。

## レビュアー目線の観点（3 で使う）

geas のしくみに引きつけた観点。「この仕様書を人がレビューするなら、何を聞くか」の候補で、上から順に当てはめ、読み取れないものを聞く。

- **上限と範囲**：数量・金額・件数が上限を超えたら、どうなるか。（型の範囲、写像の `max`、検査器が示せない書き込みの扱い）
- **同時に来たら**：同じものを2人が同時に操作したら。画面が古いまま上書きしたら。（直列化の担い手、書込の版の確認は未決）
- **外が返事しないとき**：決済や倉庫が遅い・返さない・2回返したら。期限は。（トリガの期限、冪等キー、開発用の模擬）
- **取り消しと削除**：途中でやめられるか。消したとき、参照している側はどうなるか。（`delete` の参照元の扱い、遷移の拒否）
- **状態の抜け**：終わった状態からさらに操作したら。（遷移と拒否の理由）
- **お金と端数**：丸めの方向、通貨が混ざる注文、割合の掛け算。（丸めの指定、通貨）
- **無い・空**：未入力、空の一覧、見つからないとき。（`required`、存在の確認）

観点は、検査器の問いと重なるものがある（丸めの方向、存在しない場合など）。検査器が問いにしているものは検査器に任せ、ここでは聞かない。

## 終わり方

人が仕様書を読み終えて、検査にエラーも問いもなく、変異検査の生き残りの扱い（足した／そのまま）が決まっていること。そのうえで `geas rust` に進む。手で書くコードを増やさない（計画書・`.geas` に現れない手書きコードは、無くす方向で考える）。
